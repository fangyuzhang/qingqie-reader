### 1.2 重构清单（问题 → 新设计）

| # | 原设计 | 新设计 | 理由 |
|---|---|---|---|
| R1 | SharedPreferences 当数据库（shelf/reading_position_/reader_bookmarks_/novel_meta_/chapter_ 前缀键） | **sqflite 六张表**（见 03 文档）+ DAO | 索引查询、级联删除、schema 迁移、批量操作 |
| R2 | `LibraryState` 2041 行上帝对象 | 4 个 ViewModel：`BookshelfViewModel / ReaderViewModel / SourceViewModel / SettingsViewModel`（provider 管理） | 单一职责、可测试、按页面粒度刷新 |
| R3 | `OfflineNovelRepository` 一个仓库混合远程+缓存+本地+下载队列 | 3 个 Repository：`BookshelfRepository`（书架/分类/导入）、`ReaderRepository`（章节/进度/书签/笔记）、`BookSourceRepository`（书源 CRUD/校验/导入导出）；网络与文件下沉 DataSource | 边界清晰，UI 不感知数据来源 |
| R4 | lib/ 扁平 133 文件 | `core / data(model,local,remote,parser,repository,file) / feature(...)` 四层 | 依赖单向，新人可读 |
| R5 | TXT `utf8.decoder` 硬解码 | BOM 检测 → UTF-8 严格试探 → GB18030（`charset_converter`）→ 失败友好报错 | 修复 GBK 小说乱码（真实缺陷） |
| R6 | UI 直接调 state 且触发 IO | UI → ViewModel → Repository → DataSource，IO 全在 data 层 | 落实分层约束 |
| R7 | 备份=全量 KV dump | 结构化 JSON（books/progress/bookmarks/notes/categories/sources 分表导出） | 可读、可按需恢复、向前兼容 |

## 3. 迭代路线图（每步保持可编译可运行）

| 里程碑 | 内容 | 验收标准 |
|---|---|---|
| **M1 可运行原型** | 项目骨架 → sqflite 六表 → TXT/EPUB 导入 → 书架列表+分类+搜索+立体书架 → 阅读器（滚动+分页+排版+进度+书签） | 真机导入 TXT/EPUB，阅读、进度、书签全链路可用 |
| **M2 书源与标注** | 书源 YAML 引擎 → 书源管理页（导入/导出/启禁/校验/排序）→ 在线搜索 → 章节/正文抓取 → 划线/批注/书摘 → 章内查找 | 书源搜索→加书架→在线阅读→写批注全链路 |
| **M3 备份与打磨** | 备份导出/导入 → 笔记列表 → 金句卡片导出（canvas）→ 异常文案打磨 → README/协议/CI | 备份可恢复；`flutter analyze` 零 warning |

性能优化（分页缓存、章节预加载、书架懒加载）全部放二期迭代，**MVP 不过度设计**。
