## 1. 项目概况

| 项 | 值 |
|---|---|
| 定位 | 轻小说文库（wenku8.net）Flutter 迁移版，Android 优先 |
| 规模 | 424 个 Dart 文件；`lib/` 下 133 个文件为**扁平布局**（无子目录分层）+ `listening/`（听书 10 个）+ `updates/`（更新 3 个） |

## 3. 模块划分与实现方式

### 3.1 入口与依赖注入（main.dart）

```dart
// 手工装配，无 DI 框架
final state = await LibraryState.load();                    // 全局状态（2041 行上帝对象）
final remote = LegacyWenkuRepository(...);                  // wenku8 站点（JNI）
final repository = OfflineNovelRepository(                  // 组合仓库
  remote: remote, cache: await OfflineCacheStore.forApp(),
  local: await LocalBookStore.forApp(), network: network,
);
runApp(NovelApp(state: state, repository: repository, ...));
```

**评价**：组合式仓库思路正确（remote + cache + local 三数据源合一），但 `LibraryState` 承载了书架、阅读设置、分类、排序、字体、历史、性能偏好等**所有全局状态**，且大量 UI 直接读它——这是最需要拆分的点。

### 3.2 状态管理

| 机制 | 实现 |
|---|---|
| `LibraryState extends ChangeNotifier` | 2041 行；内含 `applicationChanges / glassChanges / readerSettingsChanges / navigationChanges / readerBehaviorChanges / organization` 等多个子 notifier |
| Scope 传递 | `WenkuFeaturesScope / ListeningScope / PerformanceScope`（InheritedWidget） |
| 页面级状态 | 各 Page 内部 `setState`（pages.dart 7119 行） |

**评价**：没有 ViewModel 概念；「状态持有 + 业务逻辑 + 部分 IO」混在 ChangeNotifier 里（如 `LibraryState` 直接操作 SharedPreferences）。

### 3.3 Repository 层（设计良好，保留思路）

```dart
abstract interface class NovelRepository {
  Future<List<Novel>> list();
  Future<List<Novel>> search(String query);
  Future<Novel?> find(int id);
  Future<Novel> detail(Novel novel);
  Future<List<NovelChapter>> chapters(int id);
  Future<String> chapterContent(int novelId, NovelChapter chapter);
}
```
实现类：`LegacyWenkuRepository`（JNI 站点）、`OfflineNovelRepository`（缓存+本地+远程+下载队列，622 行）、`LibrarySearchRepository`（装饰器加搜索）、`PublicationNovelRepository`、`DemoNovelRepository`（非安卓）。

### 3.4 数据层实现

| 数据 | 存储方式 | 键/路径约定 |
|---|---|---|
| 书架列表 | SharedPreferences | `shelf`（List<String> id） |
| 阅读进度 | SharedPreferences | `reading_position_<id>`（JSON） |
| 书签 | SharedPreferences | `reader_bookmarks_<id>`（JSON 数组） |
| 章节缓存 | SharedPreferences + 文件 | `chapter_<id>_<cid>`；`OfflineCacheStore` 目录文件 + epoch 失效 |
| 书籍元数据 | SharedPreferences | `novel_meta_<id>` |
| 本地书 | 文件系统 | `LocalBookStore`：原文件 digest + bodies + images + 每书 metadata JSON + 系列 |
| 备份 | JSON 全量 KV | `library_backup.dart`：`{format: wenku8-local-backup, records: {...全部键}}`，上限 4 MiB，`compute()`  isolate 编解码 |

**评价**：**SharedPreferences 当数据库**——无索引、无级联删除、无迁移机制、大 JSON 反复全量解析。这是重构为 sqflite 的核心动因。

### 3.5 阅读器（能力最完整的模块）

| `reader_paged_view.dart`(1111) | 翻页视图：5 种翻页动效（段落接续/平移/覆盖/纸页/无） |

### 3.6 立体书架（用户指定「照抄」的模块）

```dart
// archive_shelf_geometry.dart —— 2.5D 轴测投影的全部数学
static const depthX = .66, depthY = -.30, rowStep = 2.5;
static double spineFor(double w) => (w * .043).clamp(14.0, 18.0);   // 书脊宽
static double pitchFor(double w) => spineFor(w) + 11;               // 书间距（紧贴成一排）
static double coverFor(double w) => (w * .32).clamp(100.0, 128.0);  // 封面宽
static double railY(double d) => (d.clamp(-7, 7)) * 2.5 + d * d * .45;  // 整排成弧
static Offset origin(double cover, double height, double weight) {
  final pull = cover * .84 * weight * (1.24 - .24 * weight);        // 向左拉出
  final lift = weight * weight * (3 - 2 * weight);                  // smoothstep 上浮
  return Offset(-pull * depthX, baseY(...) - pull * depthY - height * .60 * lift);
}
// archive_wave.dart —— weight = cos(d / 1.48 * π/2)² 连续选中量 + 循环槽位
```

**评价**：算法与数据完全解耦（纯函数几何），可移植性极强——这是本次重构要**原样保留算法、重写数据绑定**的部分。

### 3.7 本地导入链

```
SAF 选择文件（book_documents.dart MethodChannel）
  → local_book_importer（大小校验 →  digest → 分派解析）
    → TXT: local_text_import（流式 utf8.decoder，4000 字片段，章节正则拆分，上限 10000 章）
    → EPUB: local_books.dart _epub()（archive+xml+html，含内嵌图片尺寸探测）
  → LocalBookStore 落盘（bodies 文件 + metadata JSON + 系列推断）
```

**关键缺陷**：TXT 走 `utf8.decoder` **硬解码**，GBK/GB18030 小说会乱码——实际靠原生 document bridge 预先转码（`LocalBookInput.text`），Dart 层无编码检测。新项目用 `charset_converter` 在 Dart 层解决。

### 3.8 导入上限（book_import_limits.dart）

单书 256 MiB、EPUB 单独上限、按扩展名的友好文案——**保留该设计**。

### 4.2 需重构（问题 → 方案）

| # | 问题 | 影响 | 重构方案 |
|---|---|---|---|
| 1 | `LibraryState` 2041 行上帝对象 | 改一处牵全身，无法单测 | 按功能拆 4 个 ViewModel（书架/阅读/书源/设置），provider 注入 |

## 5. 结论

原项目是一个**阅读器内核极其成熟、但数据层与状态层老化、且与单一站点深度耦合**的项目。重构策略：

- **保留**：立体书架几何（约 40 行纯数学）、分页/查找/自动滚/金句卡片/偏好模型/导入上限 的设计与算法；
- **重构**：数据层（SharedPreferences → sqflite 六表）、状态层（上帝对象 → 4 ViewModel）、仓库层（明确三类 Repository 边界）、TXT 编码；
- **删除**：wenku8 账号/评论/收藏同步/JNI/听书/插画/网盘同步（约 25 个文件，二期按需回收）；
- **新增**：YAML 书源规范 + 规则引擎 + 书源管理器 + sqflite 数据层 + MVVM 骨架。

预计保留原项目约 **30% 代码资产**（算法与设计），新增约 **60%**，删除约 **10%**（站点绑定部分在 master 中占比不高，但解除耦合的收益最大）。
